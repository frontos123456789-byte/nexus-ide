# Юридические страницы (EULA и Privacy Policy)

Публичные страницы (доступны без входа, не требуют БД):

* `/legal/eula` — End User License Agreement
* `/legal/privacy` — Privacy Policy

Тексты на английском; описывают реальное поведение приложения (что читается из Vercel, что хранится, как шифруется токен,
сроки жизни сессий). Всё, что является **решением владельца**, вынесено в `src/lib/legal/config.ts` и по умолчанию пустое.

## Как это работает

* Пустое поле → на странице жёлтый плейсхолдер `[OWNER TO COMPLETE: …]`, вверху баннер **Draft — Not ready for publication**
  со списком недостающих пунктов, страница отдаётся с `noindex`.
* Баннер и `noindex` исчезают только когда **заполнены все поля нужного документа** и владелец вручную выставил
  `OWNER_REVIEW.legalReviewConfirmed = true` (после проверки юристом).
* Ссылки на страницы есть на экране входа, в настройках аккаунта и в панели Vercel Monitor (до и после подключения).

## Что должен предоставить владелец

| Поле в `OWNER` | Что нужно |
|---|---|
| `operatorName` | Юридическое лицо / ФИО оператора |
| `operatorAddress` | Почтовый адрес |
| `contactEmail` | Рабочая почта для юридических и privacy-обращений |
| `effectiveDate` | Дата вступления в силу |
| `minimumAge` | Минимальный возраст / условия допуска |
| `pricing` | Бесплатно или платно, условия оплаты и возврата |
| `governingLaw` | Применимое право и юрисдикция |
| `databaseHosting` | Провайдер PostgreSQL (`DATABASE_URL`) |
| `dataLocation` | Регион хранения, трансграничная передача и гарантии |
| `legalBasis` | Применимый режим (GDPR и т. п.), правовые основания, права пользователей |
| `revokedConnectionRetention` | Срок хранения записи об отключённом подключении |
| `sessionRowRetention` | Срок хранения истёкших/отозванных сессий |
| `auditLogRetention` | Срок хранения audit-логов |
| `accountDeletionResponse` | Как запросить удаление/копию данных и срок ответа |
| `incidentNotification` | Обязательства по уведомлению об утечках |

## Известные расхождения кода и политики (решить владельцу)

* Нет автоматической очистки `sessions` и `integration_audit_logs` — сроки хранения заданы пустыми, пока не принято решение
  и не реализована очистка.
* Нет самообслуживаемого удаления аккаунта и экспорта данных — в политике указано обращение по e-mail.
* Запись об отключённом подключении (`connected_providers`, без токена) остаётся в БД.
